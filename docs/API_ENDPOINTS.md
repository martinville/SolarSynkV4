# Cloud API endpoint inventory

This is the complete inventory of endpoints used by SolarSynkV4 and the additional V3 endpoints now used for telemetry. It is **not** a claim to enumerate every private endpoint in the Sunsynk or Inteless services. The vendor has not provided a complete public API specification. Behavior below is source-confirmed from the linked code, not validated with a live account in this checkout. The same endpoint paths are used with the chosen host: `api.sunsynk.net` or `pv.inteless.com`.

| Method and path | Request fields | Response structure used | Purpose and source |
| --- | --- | --- | --- |
| GET `/anonymous/publicKey` | Query: `source`, `nonce`, `sign` | `data` is an RSA public key | Encrypt login password; [V3 gettoken.py](https://github.com/martinville/solarsynkv3/blob/main/gettoken.py) |
| POST `/oauth/token/new` | JSON: `client_id`, `grant_type`, RSA-encrypted `password`, `source`, `username`, `nonce`, `sign` | `data.access_token`, optional `expires_in` | Authenticate; [V3 gettoken.py](https://github.com/martinville/solarsynkv3/blob/main/gettoken.py) |
| GET `/api/v1/plants` | Query: `page`, `limit` | `data.infos[]`, optional `total`; plant `id`, `name` | Paginate accessible plants; [sunsynk-api-client](https://github.com/jamesridgway/sunsynk-api-client) and [bmerry discovery example](https://gist.github.com/bmerry/1f9317485830e736974c98cb1e5fd3b5) |
| GET `/api/v1/plant/{id}/inverters` | Path plant ID; query `page`, `limit`, `status=-1`, `type=-2` | `data.infos[]`, optional `total`; inverter `sn`, `alias`, `model`, `status`, `updateAt` | Paginate accessible inverters; same discovery sources. The status/type filters are required by the observed cloud binding error. |
| GET `/api/v1/inverter/{sn}` | Path serial | `data` object with `sn`, `alias`, `status`, `updateAt`, `pac`, daily/monthly/yearly/total energy and model fields | Identity, availability and summary; [V3 getapi.py](https://github.com/martinville/solarsynkv3/blob/main/getapi.py) |
| GET `/api/v1/inverter/{sn}/realtime/input` | Path serial | `data.pac`, `etoday`, `etotal`, `grid_tip_power`, `pvIV[]` with `ppv`, `vpv`, `ipv` | PV totals and every returned MPPT array entry; V3 getapi.py |
| GET `/api/v1/inverter/battery/{sn}/realtime` | Path serial; query `sn`, `lan=en` | `data` scalar SOC, battery power, current, voltage, temperature, charge/discharge energy and BMS fields | Battery telemetry; V3 getapi.py |
| GET `/api/v1/inverter/grid/{sn}/realtime` | Path serial; query `sn` | `data.pac`, `qac`, `fac`, `pf`, import/export energy, `vip[]` with phase `volt`, `current`, `power`, optional `limiterPowerArr[]` | Grid and per-phase telemetry; V3 getapi.py |
| GET `/api/v1/inverter/load/{sn}/realtime` | Path serial; query `sn` | `data.totalPower`, `upsPowerTotal`, load energy and `vip[]` | Load and per-phase telemetry; V3 getapi.py |
| GET `/api/v1/inverter/{sn}/realtime/output` | Path serial | `data.pInv`, `pac`, `fac`, `vip[]` | AC output and per-phase telemetry; V3 getapi.py |
| GET `/api/v1/inverter/{sn}/output/day` | Path serial; query `lan=en`, current `date`, `column=dc_temp,igbt_temp` | `data.infos[]`, each with `records[]` containing `value` | Latest returned DC and IGBT temperature values; V3 getapi.py |
| GET `/api/v1/inverter/{sn}/flow` | Path serial | `data` object with PV, battery, grid, load and generator flow powers plus flags | Power flow values; V3 getapi.py |
| GET `/api/v1/common/setting/{sn}/read` | Path serial | Complete `data` settings object with `sn` and battery/system-mode fields | Read settings and confirm later cloud read-back; [V3 getapi.py](https://github.com/martinville/solarsynkv3/blob/main/getapi.py) |
| POST `/api/v1/common/setting/{sn}/set` | Path serial; JSON page-specific Battery, System mode, Aux Load, or Advanced fields, including `sn` and unchanged group fields | Success/acceptance message; physical application is not proven | Submit a guarded settings change; [V3 settingsmanager.py](https://github.com/martinville/solarsynkv3/blob/main/settingsmanager.py) |

V4's parser iterates through the full `pvIV` and `vip` arrays. A four MPPT response creates four power, four voltage and four current entities. Numeric `limiterPowerArr` entries are exposed by position with no inferred unit. Missing entries are omitted, never filled with zero. A test covers four MPPTs and four phases. The `mpptIV` key is accepted by V4 if present, based on other client source, but it has not been confirmed in V3's `getapi.py` or against a live account.

V4 exposes additional safe scalar fields from the settings read response as **read-only diagnostic sensors**. The 104 mapped controls use reviewed page templates and validation. These cover the Battery, System mode, Aux Load, and the reviewed Advanced solar power control, including `peakAndVallery` (Use timer). Advanced writes preserve unchanged Grid and protection fields required by its captured portal payload. Grid and parallel topology controls are excluded; unknown settings remain read-only. Account permissions, master/slave routing, response variations and physical application still require live validation for each model and cloud service.

The Aux Load payload field list was verified against a portal Save capture and cross-checked against the [Solar-Sunsynk service schemas](https://github.com/MorneSaunders360/Solar-Sunsynk/blob/main/custom_components/solar_sunsynk/const.py). Battery, System mode, Aux Load, and Advanced payloads were compared with portal Save captures supplied for this inverter. A successful cloud response or read-back does not establish that the physical inverter applied a setting.

The browser capture confirms `POST https://api.sunsynk.net/api/v1/common/setting/{sn}/set` with `Content-Type: application/json` and `Authorization: Bearer <token>`. V4 obtains its own token through `/oauth/token/new` and inserts the selected inverter serial in both `{sn}` and the JSON `sn` field. Browser-only `Origin`, `Referer`, and `sec-*` headers are not needed by the Python client. HTTP 200 alone is not treated as confirmation: V4 checks the API message and then reads settings back.
